# 三维场景交互代理 · 示范学习原型

一个可运行的本地示范学习（imitation learning）原型：在自制三维空间中，角色根据**可观察特征**选择接近物件、检查标记或操作装置；由独立的**规则示范策略**产生训练轨迹；再用这些轨迹训练一个**小型本地模型**（MLP），在引擎中以完整交互回合执行任务。

全部推理在本地完成，**不调用任何远程聊天接口**，也不在测试场景中回放示范策略来伪造学得代理的成功。

---

## 快速开始

```bash
npm install
npm run dev          # 打开 http://127.0.0.1:5173
```

首次运行需要数据与模型；仓库已包含生成好的产物，若要从零重训：

```bash
npm run demo:collect   # 生成示范数据（训练集 / 验证集，不同种子）
npm run demo:train     # 行为克隆 + DAgger，写出 public/models/learned-model.json
npm run demo:evaluate  # 完整回合评估，写出 reports/evaluation.json
npm run dev
```

界面操作：

1. 右侧「驱动模式」选择 **学得**，点击 **▶ 代理驱动**，即可看到小模型逐步驱动角色完成整个回合。
2. 切换 **规则** / **随机** / **示范** / **手动** 对比不同策略的行为。
3. 左侧三维视口显示角色、物件、装置、目标卡；右侧面板实时显示**策略动作**、**输入观测**与**失败回写日志**。
4. 交换条件（标准 / 歧义 / 拥挤 / 不可解）或种子，检验不同布局。

## 任务与规则（明确的状态编码、动作含义与合法性）

**目标卡**给出一个颜色 + 形状 + 刻符三元组。场景中散布 6 个固定物：物件（object）与装置（device）。

- 场景中**恰好一个装置**的完整三元组与目标卡一致。
- 装置上刻有刻符，但**在未读取前不可见**；部分装置刻符**模糊**，近距离检查只能确认“需要额外视野”。
- 物件始终显示自身刻符，用于制造“颜色形状相似但刻符不同”的干扰。

### 动作（20 个，固定索引）

| 动作 | 索引 | 含义 | 合法性 |
|---|---|---|---|
| 接近 #i | `0..5` | 走到装置/物件旁（沿最短路） | 可达且步数够 |
| 检查 #i | `6..11` | 读取装置标记 | 必须相邻；仅装置；未检查过 |
| 操作 #i | `12..17` | 启动装置 | 必须相邻；仅装置；**已读取该装置刻符**（禁止盲目操作） |
| 请求额外视野 | `18` | 一次性读取所有装置刻符，消耗 2 步 | 每回合一次 |
| 拒绝执行 | `19` | 安全放弃，回合结束 | 总是合法 |

### 观测（139 维，只含可观察特征）

- 每个槽位 20 维：存在、是否装置、颜色 3、形状 3、**已知**刻符 3、刻符是否已知、是否模糊、路径距离、可达、相邻、颜色相符、形状相符、刻符相符、是否候选。
- 全局：目标颜色/形状/刻符各 3 维、已检查槽位 6 维、是否已请求视野、角色坐标、剩余步数。

**关键约束：** 观测向量中没有任何 `hiddenTargetSlot` / `hiddenTargetGlyph` / `targetSlot` 字段。隐藏目标只在评估时用于判定成功与否；策略与模型只能通过颜色、形状、刻符与空间关系推断。测试用例 `tests/invariants.spec.ts` 会扫描整个观测与动作流程验证这一点。

## 示范代理（独立于学得模型）

规则示范策略（`src/core/policies.ts` 的 `makeRuleDemonstrator`）读取**同一份观测**，按以下顺序决策：

1. 只有一个装置满足完整三元组 → 接近并操作；
2. 存在未读/模糊刻符且证据不足 → **请求额外视野**（若已被消耗则检查/拒绝）；
3. 近距离检查清晰刻符，逐步排除；
4. 若全部刻符已知仍有 ≥2 个装置不可区分（观测冲突），或根本无匹配装置 → **拒绝执行**。

它还是**有状态的代理内核**：引擎会把“非法动作原因 / 操作错误装置”作为 `feedback` 回写，内核记录并在同一回合内避开被拒绝的动作。界面日志会显示这些失败反馈。

## 学习管线

```
collect.ts  →  data/train-demonstrations.json      (380 回合，训练种子)
            →  data/validation-demonstrations.json (100 回合，验证种子)
train.ts    →  行为克隆 + 8 轮 DAgger
            →  public/models/learned-model.json + manifest.json（版本化）
evaluate.ts →  reports/evaluation.json（完整回合指标 + 失败分类）
```

- 模型结构：`139 → 96 → 96 → 20` 的 MLP，ReLU + Softmax，Adam 训练。
- 学得策略**不是**直接 argmax：引擎的合法性掩码把非法动作 logit 置为 `-1e9`，因此模型只会在合法动作中取舍。
- 模型版本形如 `local-bc-dagger-4bc463a8`，由权重与种子哈希得到；`public/models/manifest.json` 保留最近若干版本。
- 训练/验证/隐藏种子互不重叠（自动断言），防止记住对象编号或固定摆放。

### 当前完整回合结果（隐藏种子，325 回合）

| 策略 | 成功 | 安全拒绝 | 错操作 | 放弃 | 随机下限 |
|---|---|---|---|---|---|
| 规则示范 | 300 | 25 | 0 | 0 | — |
| **学得策略** | 283 | 25 | 8 | 9 | — |
| 随机合法 | 12 | 16 | 31 | 15 预算耗尽 | — |

学得策略合计通过 **308 / 325 ≈ 94.8%**（成功 283 + 安全拒绝 25），随机合法仅 28 / 325。

按条件拆分学得策略（`reports/evaluation.json` 的 `failureBreakdown`）：

| 条件 | 通过 | 误操作 | 放弃 |
|---|---|---|---|
| 标准 | 94/100 | 3 | 3 |
| 歧义 | 95/100 | 4 | 1 |
| 拥挤 | 94/100 | 1 | 5 |
| 不可解 | **25/25 安全拒绝** | 0 | 0 |

学得策略在训练中从未见过隐藏种子；它在不可解场景中学会了安全拒绝，在可解场景中主要失败于少数“检查到不符刻符后仍误操作”的状态。**学得策略没有被替换成示范策略**——评估脚本对 `learned` 策略独立运行，并使用 `hiddenTargetSlot` 仅在回合结束后判定。

## 已知限制

- 这是原型：场景为 13×13 网格、6 个固定物、单一目标卡；未包含多房间、动态障碍或连续控制。
- 学得模型在隐藏集上约 94.8% 通过（283 成功 + 25 安全拒绝），失败集中在少数状态；可重训（`npm run demo:all`）以改进。
- 三维渲染在无 GPU 的无头环境使用 SwiftShader，帧率较低但功能一致。
