# 三维场景交互代理 · 示范学习原型

一个可运行的本地示范学习（imitation learning）原型：在自制三维空间中，角色根据**可观察特征**选择接近物件、检查标记或操作装置；由独立的**规则示范策略**产生训练轨迹；再用这些轨迹训练一个**小型本地模型**（MLP），在引擎中以完整交互回合执行任务。

全部推理在本地完成，**不调用任何远程聊天接口**，也不在测试场景中回放示范策略来伪造学得代理的成功。

---

## 快速开始

```bash
npm install
npm run dev          # 打开 http://127.0.0.1:5173
```

首次运行需要数据与模型；仓库已包含生成好的产物，若要从零重训：

```bash
npm run demo:collect   # 生成示范数据（训练集 / 验证集，不同种子）
npm run demo:train     # 行为克隆 + DAgger，写出 public/models/learned-model.json
npm run demo:evaluate  # 完整回合评估，写出 reports/evaluation.json
npm run dev
```

界面操作：

1. 右侧「驱动模式」选择 **学得**，点击 **▶ 代理驱动**，即可看到小模型逐步驱动角色完成整个回合。
2. 选择 **仲裁** 进入「仲裁代理」图形入口（详见下文），可在 **线性 softmax** 与 **小型 MLP** 两种策略表示间切换，并调节置信阈值与低置信处理方式。
3. 切换 **规则** / **随机** / **示范** / **手动** 对比不同策略的行为。
4. 左侧三维视口显示角色、物件、装置、目标卡；右侧面板实时显示**策略动作**、**输入观测**、**仲裁来源**与**失败回写日志**。
5. 交换条件（标准 / 歧义 / 拥挤 / 不可解）或种子，检验不同布局；种子 3000–3099 是**训练/验证从未出现过的新布局**。

## 仲裁代理的图形入口（示范代理生产接点）

示范代理不是只留在架构说明里：它作为**仲裁器的转交目标**接进了运行原型，并在界面上有明确的图形入口。

- 入口按钮：右侧「驱动模式」中的 **仲裁**（`index.html` 的 `[data-driver='arbiter']`）。
- 控制面板：**仲裁代理** 面板，包含
  - **策略表示** `#arbiter-model`：线性 softmax / 小型 MLP；
  - **低置信处理** `#arbiter-mode`：先补观测再转交 / 直接转交示范者 / 只补观测；
  - **置信阈值** `#arbiter-threshold`；
  - 实时统计 `#arbiter-stats`：决策 / 补观测 / 转交示范 / 低置信 / 本回合示范请求；
  - 异常提示 `#arbiter-error`：模型或配置加载失败时在界面显式报错，不会静默降级。
- 每步动作在「回合日志」里带来源标记 `模型` / `补观测` / `转交示范`，右侧「当前动作」同时给出置信度、阈值、前向次数与 MAC 数；回合结束横幅给出 `示范请求 N 次 · 前向 N 次`。
- 触发条件由 `public/models/arbiter-config.json` 持久化，页面启动时自动载入；阈值/模式改动会在下一次决策立即生效。

界面只负责**观察与调参**；所有实验指标由命令行脚本重算，见下文。命令行仅辅助示范代理，图形入口是主要交互方式。

## 策略表示实验：线性 vs 小型非线性模型

两种表示接收**完全相同的 139 维可观察特征**，使用**相同的训练数据、优化器、行为克隆 + 8 轮 DAgger**，唯一差异是网络结构。

| | 线性 softmax | 小型 MLP |
|---|---|---|
| 结构 | `139 → 20` | `139 → 96 → 96 → 20` |
| 参数 | 400 | 18 832 |
| 每前向 MAC | 2 780 | 24 480 |
| 产物 | `public/models/experiment-linear.json` | `public/models/experiment-mlp.json` |

**固定划分**（互不重叠，报告内 `splits` 记录并哈希）：训练 380 回合（种子 1000–1279、1600–1699）；验证 100 回合（2000–2079、2600–2619，**仅用于阈值标定**）；隐藏评估 325 回合（9000–9099 / 9300–9399 / 9500–9524）；**新布局 100 回合（3000–3099）**。隐藏集与新布局从不参与训练或阈值选择。

### 触发条件（已持久化）

在固定验证集上逐模型、逐模式网格搜索阈值 `[0.4, 0.55, 0.7, 0.8, 0.9]`，主键为**最少错误操作**，并列时取**更少示范请求**，再并列取更高通过数。两种模型、三种模式均选出 **0.80**；生产快照 `public/models/arbiter-config.json` 采用 `{threshold: 0.8, mode: "both"}`。

### 结果（完整回合，由引擎重算）

隐藏评估集 225 回合（标准 100 + 歧义 100 + 不可解 25）按各模式最优阈值运行：

| 表示 | 模式 | 通过 | 错操作 | 示范请求 | 前向/回合 | MAC/回合 |
|---|---|---|---|---|---|---|
| 线性 | defer | **223/225** | 1 | 117 | 2.90 | 8 056 |
| 线性 | gather | 222/225 | 2 | 72 | 2.96 | 8 229 |
| 线性 | both | 222/225 | 2 | 72 | 2.96 | 8 229 |
| MLP | defer | 222/225 | 3 | 42 | 2.90 | 70 938 |
| MLP | gather | 221/225 | 4 | 12 | 2.92 | 71 482 |
| MLP | both | 221/225 | 4 | 12 | 2.92 | 71 482 |

新布局 100 回合（训练/验证从未见过）：

| 表示 | 模式 | 通过 | 错操作 | 示范请求 | 触发回合 |
|---|---|---|---|---|---|
| 线性 | defer | 98/100 | 1 | 63 | 46 |
| 线性 | gather | 98/100 | 1 | 28 | 28 |
| 线性 | both | **98/100** | 1 | 28 | 28 |
| MLP | defer | 94/100 | 1 | 29 | 28 |
| MLP | gather | 93/100 | 2 | 20 | 20 |
| MLP | both | 93/100 | 2 | 20 | 20 |

基线（同一批新布局）：规则示范者 **100/100、错操作 0**（但不使用模型，是上界参考）；随机合法 **9/100**。

**结论与取舍：**

1. **在新布局上线性表示更稳**：线性 98/100、错操作 1；MLP 93–94/100、错操作 1–2。MLP 参数多 47 倍、前向 MAC 多约 8.8 倍，却没有换来更好的未知布局泛化——数据只有 380 回合、1 040 个状态样本，非线性容量主要拟合了训练分布。
2. **示范请求与正确性可调换**：MLP 在 `defer` 下通过略高但请求最多；`gather`/`both` 把请求压到约 1/3（新布局 63 → 28），代价是歧义集错操作 +1。线性在 `both` 下同时拿到最低错操作与较低请求，是综合最优的默认配置。
3. **补观测确实替代了一部分示范**：线性新布局从 `defer` 的 63 次请求降到 `both` 的 28 次，通过率不变；说明“先补观测再重推断”在本任务里是有效的低置信消解手段，而不是纯装饰。
4. **推理成本**：线性每回合约 8 千 MAC、12–18 µs；MLP 约 7 万 MAC、52–70 µs。在本机两者都在交互预算内，但线性便宜约一个数量级，且可解释（每维特征权重可直接读出）。

### 少量示范扫描（布局变化 × 示范量）

用 `≤N` 个示范回合重训两种表示，在验证集重新标定阈值后在**新布局**与**隐藏集**上评估；数据见 `reports/fewshot-sweep.json`。

| 示范回合 | 线性 新布局 通过/错操作/请求 | MLP 新布局 通过/错操作/请求 | 线性 隐藏 通过 | MLP 隐藏 通过 |
|---|---|---|---|---|
| 10 | 92 / 0 / 56 | 72 / 1 / 21 | 220/225 | 185/225 |
| 20 | 96 / 0 / 58 | 91 / 2 / 17 | 217/225 | 212/225 |
| 40 | **100 / 0 / 110** | 74 / 1 / 13 | **225/225** | 179/225 |
| 80 | 100 / 0 / 93 | 88 / 1 / 40 | 225/225 | 202/225 |
| 160 | 100 / 0 / 59 | 79 / 2 / 33 | 224/225 | 199/225 |
| 380 | 98 / 1 / 28 | 93 / 2 / 20 | 222/225 | 221/225 |

- 线性在 **40 回合**就达到新布局与隐藏集的通过上限，请求数从 110 降到 380 回合的 28；MLP 需要更多数据才追平，且方差更大。
- **失配讨论**：MLP 在 40–160 回合区间明显过拟合小样本（新布局 74–88），随数据增多才回升；线性几乎单调改善。这与“小样本下低容量表示更可靠”的预期一致，也是本实验把线性作为默认仲裁后端的依据。
- 注意 380 回合线性新布局回落到 98/100、请求反而只有 28——这是阈值标定在验证集上选到 0.8 后，更多训练让模型更自信、更少请求、偶尔直接误判；它不改变“线性优于 MLP”的结论，但说明请求数与正确性存在非单调权衡，需要按部署风险取舍。

### 复算与执行证据

所有“动作成功 / 推理成本”都不是文本结论，而是**由代码重算**：

```bash
npm run demo:experiment        # 重训两种表示、标定阈值、跑全部组别与少量示范，写报告/模型/触发快照
npm run demo:verify:experiment # 重新载入模型产物，逐行用引擎重算 30 行指标 + 重训重算 12 行少量示范
```

`demo:verify:experiment` 会重新训练全部 12 个少量示范模型并逐行比对，任何一行与报告不符即以非零码退出。映射关系：

- **动作成功** ← `runEpisode` 的 `success` / `safeRefusal` / `endReason === "wrong-target"`，逐种子统计；
- **示范请求** ← 引擎 `demonstrationRequests`，在一次动作的来源为 `demonstrator` 时 +1；
- **推理成本** ← 仲裁器每次决策写入的 `cost`（前向次数、特征检查数、MAC），引擎累加到 `EpisodeResult.inference`；
- **计时** ← `runEpisode` 用 `performance.now()` 包裹 `decide`，仅作本机参考，**不参与断言**（复核脚本只校验确定性指标）。

### 策略表示讨论中的假设（单列待验）

以下判断**尚未被本仓库实验证明**，只是讨论前提，列出以便后续验证，不应视为结论：

1. 假设线性 softmax 的逐维权重足以覆盖本任务的可观察特征交互；若场景引入需要特征组合（“近距离 + 已检查 + 模糊”）的决策，线性可能系统性欠拟合，需用带特征交叉的表示重测。
2. 假设 `0.80` 阈值在**部署分布**上同样最优；当前只在 100 回合验证集标定，未覆盖真实使用中的长尾布局。
3. 假设“示范请求”的成本对所有低置信状态相同；实际上转交示范者在生产环境可能有人工时延，需按状态类型分别定价后再比较。
4. 假设补观测动作总能获得新信息；当所有装置已读尽时这是假前提，`gatherAction` 返回 null 时才回落到转交，实际收益需按“可获得信息量”重新度量。
5. 假设 MLP 的劣势来自样本量而非结构本身；尚未做同参数量的线性/非线性消融，也未做多随机种子重复训练来估计方差。
6. 假设新布局种子 3000–3099 代表“未知布局”；它们只改变出生点与部分摆放，未覆盖全新物体数或全新规则。

## 任务与规则（明确的状态编码、动作含义与合法性）

**目标卡**给出一个颜色 + 形状 + 刻符三元组。场景中散布 6 个固定物：物件（object）与装置（device）。

- 场景中**恰好一个装置**的完整三元组与目标卡一致。
- 装置上刻有刻符，但**在未读取前不可见**；部分装置刻符**模糊**，近距离检查只能确认“需要额外视野”。
- 物件始终显示自身刻符，用于制造“颜色形状相似但刻符不同”的干扰。

### 动作（20 个，固定索引）

| 动作 | 索引 | 含义 | 合法性 |
|---|---|---|---|
| 接近 #i | `0..5` | 走到装置/物件旁（沿最短路） | 可达且步数够 |
| 检查 #i | `6..11` | 读取装置标记 | 必须相邻；仅装置；未检查过 |
| 操作 #i | `12..17` | 启动装置 | 必须相邻；仅装置；**已读取该装置刻符**（禁止盲目操作） |
| 请求额外视野 | `18` | 一次性读取所有装置刻符，消耗 2 步 | 每回合一次 |
| 拒绝执行 | `19` | 安全放弃，回合结束 | 总是合法 |

### 观测（139 维，只含可观察特征）

- 每个槽位 20 维：存在、是否装置、颜色 3、形状 3、**已知**刻符 3、刻符是否已知、是否模糊、路径距离、可达、相邻、颜色相符、形状相符、刻符相符、是否候选。
- 全局：目标颜色/形状/刻符各 3 维、已检查槽位 6 维、是否已请求视野、角色坐标、剩余步数。

**关键约束：** 观测向量中没有任何 `hiddenTargetSlot` / `hiddenTargetGlyph` / `targetSlot` 字段。隐藏目标只在评估时用于判定成功与否；策略与模型只能通过颜色、形状、刻符与空间关系推断。测试用例 `tests/invariants.spec.ts` 会扫描整个观测与动作流程验证这一点。

## 示范代理（独立于学得模型）

规则示范策略（`src/core/policies.ts` 的 `makeRuleDemonstrator`）读取**同一份观测**，按以下顺序决策：

1. 只有一个装置满足完整三元组 → 接近并操作；
2. 存在未读/模糊刻符且证据不足 → **请求额外视野**（若已被消耗则检查/拒绝）；
3. 近距离检查清晰刻符，逐步排除；
4. 若全部刻符已知仍有 ≥2 个装置不可区分（观测冲突），或根本无匹配装置 → **拒绝执行**。

它还是**有状态的代理内核**：引擎会把“非法动作原因 / 操作错误装置”作为 `feedback` 回写，内核记录并在同一回合内避开被拒绝的动作。界面日志会显示这些失败反馈。

示范代理的生产接点即上文**仲裁代理**：`src/core/arbiter.ts` 的低置信分支直接调用 `makeRuleDemonstrator()` 的内核，`feedback` 通过仲裁器透传回示范者，因此在图形界面上选择“仲裁 + 直接转交示范者”时，运行的正是这个有状态代理，而不是一段架构描述。

## 学习管线

```
collect.ts  →  data/train-demonstrations.json      (380 回合，训练种子)
            →  data/validation-demonstrations.json (100 回合，验证种子)
train.ts    →  行为克隆 + 8 轮 DAgger
            →  public/models/learned-model.json + manifest.json（版本化）
evaluate.ts →  reports/evaluation.json（完整回合指标 + 失败分类）
```

- 模型结构：`139 → 96 → 96 → 20` 的 MLP，ReLU + Softmax，Adam 训练。
- 学得策略**不是**直接 argmax：引擎的合法性掩码把非法动作 logit 置为 `-1e9`，因此模型只会在合法动作中取舍。
- 模型版本形如 `local-bc-dagger-4bc463a8`，由权重与种子哈希得到；`public/models/manifest.json` 保留最近若干版本。
- 训练/验证/隐藏种子互不重叠（自动断言），防止记住对象编号或固定摆放。

### 当前完整回合结果（隐藏种子，325 回合）

| 策略 | 成功 | 安全拒绝 | 错操作 | 放弃 | 随机下限 |
|---|---|---|---|---|---|
| 规则示范 | 300 | 25 | 0 | 0 | — |
| **学得策略** | 283 | 25 | 8 | 9 | — |
| 随机合法 | 12 | 16 | 31 | 15 预算耗尽 | — |

学得策略合计通过 **308 / 325 ≈ 94.8%**（成功 283 + 安全拒绝 25），随机合法仅 28 / 325。

按条件拆分学得策略（`reports/evaluation.json` 的 `failureBreakdown`）：

| 条件 | 通过 | 误操作 | 放弃 |
|---|---|---|---|
| 标准 | 94/100 | 3 | 3 |
| 歧义 | 95/100 | 4 | 1 |
| 拥挤 | 94/100 | 1 | 5 |
| 不可解 | **25/25 安全拒绝** | 0 | 0 |

学得策略在训练中从未见过隐藏种子；它在不可解场景中学会了安全拒绝，在可解场景中主要失败于少数“检查到不符刻符后仍误操作”的状态。**学得策略没有被替换成示范策略**——评估脚本对 `learned` 策略独立运行，并使用 `hiddenTargetSlot` 仅在回合结束后判定。

上表是**旧样例**（`learned-model.json`，未接仲裁器的纯学得策略）的完整回放结果；`demo:evaluate` 与 `demo:verify` 仍会把它跑到回合结束，`train/validation` 380 + 100 回合重放零不一致。它与上文“策略表示实验”中的两种新表示是**不同产物**，不要混淆：前者是生产界面“学得”驱动的模型，后者是仲裁实验单独训练的 `experiment-linear/mlp.json`。

## 已知限制

- 这是原型：场景为 13×13 网格、6 个固定物、单一目标卡；未包含多房间、动态障碍或连续控制。
